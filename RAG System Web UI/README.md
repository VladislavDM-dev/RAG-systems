# RAG System Web UI

Веб-интерфейс для сервиса **RAG System** (Flask API на порту `11455`, префикс `/rag`):
чат с базой знаний, админ-панель и **мастер генерации служебных записок**.
Страницы взяты за основу из проекта `IndexDocuments` и адаптированы под работу
через HTTP API.

## Возможности

- **Чат**: поиск по документам с/без ИИ, SSE-стрим ответа, источники, сохранение
  избранного и истории диалогов на сервере.
- **История на сервере**: диалоги и ответы сохраняются через API
  (`/api/conversations`, `/api/answers`, `/api/history`), а не в localStorage.
- **Восстановление сессии**: после обновления страницы автоматически
  возвращается незавершённый мастер записки (или открывается последний диалог).
- **Мастер служебной записки** (команда `/create <тема>`):
  - одно окно с агентом — варианты тела записки (RAG-поиск по базе знаний),
    редактируемый текст и поля шапки из шаблона `mmo.dotx`;
  - связанные пары полей: «Кому должность ↔ ФИО», «От должность ↔ ФИО»,
    «исполнитель ↔ телефон» — выбор варианта автоподтягивает парный;
  - пошаговый предпросмотр и скачивание готового `.docx` через `/api/memo/docx`;
  - поле-структуру дают сервер: `/api/memo/template` (10 полей с русскими подписями).

## Запуск

```bat
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
SET PYTHONUTF8=1
.venv\Scripts\python.exe app.py
```

> Обязательно запускайте с `-X utf8` (или `PYTHONUTF8=1`) — иначе кириллица в
> формировании `.docx` может ломаться.

Страницы:

- `http://127.0.0.1/` — чат (вход, мастер записок, история).
- `http://127.0.0.1/admin` — админ-панель (инфо, настройки LLM, папки, синхронизация).
- `http://127.0.0.1/test-parser` — тест парсера (.doc/.docx/.pdf).

> Порт по умолчанию — `80` — требует прав администратора. Сменить порт можно
> переменной окружения `PORT` (например `set PORT=5000`).

## Настройка

| Переменная        | По умолчанию                  | Описание                          |
|-------------------|-------------------------------|-----------------------------------|
| `RAG_API_URL`     | `http://127.0.0.1:11455/rag`  | Базовый URL API сервиса RAG System|
| `PORT`            | `80`                          | Порт веб-интерфейса               |

Пример:

```bat
set RAG_API_URL=http://172.30.99.77:11455/rag
set PORT=5000
.venv\Scripts\python.exe -X utf8 app.py
```

## Как это работает

Веб-интерфейс сам не индексирует документы — запросы чата и админки проксируются
на API RAG System (через `requests`), стриминговые эндпоинты передаются как SSE.
История, избранное и генерация `.docx` хранятся в **самом веб-интерфейсе**.

Соответствие вызовов фронтенда и эндпоинтов:

| JS (браузер)          | Прокси-путь            | Целевой эндпоинт RAG System       |
|-----------------------|------------------------|-----------------------------------|
| Чат                   | `/rag/search/stream`   | `POST /rag/search/stream` (SSE)   |
| Статус синхронизации  | `/rag/engine/status`   | `GET /rag/engine/status`          |
| Запуск синхронизации  | `/rag/index`           | `POST /rag/index`                 |
| Папки                 | `/rag/folders`         | `GET/POST /rag/folders`           |
| Сохранение настроек   | `/rag/config` (PATCH)  | `PATCH /rag/config`               |
| Модели бэкенда        | `/rag/models`          | `GET /rag/models`                 |
| Парсинг файла         | `/rag/parse`           | `POST /rag/parse`                 |

Собственные эндпоинты (`/api/...`):

| Путь                          | Описание                                     |
|-------------------------------|----------------------------------------------|
| `POST /login` `/register`     | Вход / регистрация                           |
| `GET /api/history`            | Диалоги и избранные ответы                   |
| `PUT/DELETE /api/conversations(/<id>)` | Сохранение/удаление диалога          |
| `PUT/DELETE /api/answers(/<id>)`      | Сохранение/удаление избранного       |
| `POST /api/history/clear`     | Очистка всей истории                         |
| `GET /api/memo/template`      | Поля шаблона `mmo.dotx` (10 полей, подписи)  |
| `POST /api/memo/docx`         | Сборка `.docx` по значениям полей            |

## Мастер служебной записки

1. В чате: `/create <тема>`.
2. Сервер запрашивает структуру шаблона, параллельно RAG генерирует варианты
   текста и варианты значений полей из базы знаний.
3. Одно окно: выбор варианта тела (заполняет textarea) + все поля шапки.
   Поля «Дата» и «Номер» — ручные, остальные — из RAG или свои.
4. «Далее» → предпросмотр в стиле шаблона → «Скачать .docx и сохранить»:
   файл формируется через `memo_docx.py` по `docx_templates/mmo.dotx`.
5. Состояние мастера (`localStorage`) сохраняется на каждом действии — после
   перезагрузки страницы работа продолжается с того же места.

Версия клиентских скриптов задаётся в `app.py` (`MEMO_JS_VERSION`) и подставляется
в `index.html` как `?v=...` (обязательно обновляйте при правках `memo.js`/`main.js`,
иначе браузер отдаст закешированную версию).

## Тесты

```bat
.venv\Scripts\python.exe -m pytest
```

Дымовые тесты проверяют рендер страниц при недоступном API, формат запроса
прокси и корректный статус 502 при выключенном сервисе RAG System.

## Пакетная генерация записок (`generate_memos.py`)

Скрипт в корне репозитория (не здесь) массово генерирует записки в `out/`,
заполняя поля и footer (`executor`, `phone`) через Word COM (`win32com`).
Требует Python с `pywin32` — например `C:\Scripts\RAG systems\RAG System\.venv`:

```powershell
cd "C:\Scripts\RAG systems"
"C:\Scripts\RAG systems\RAG System\.venv\Scripts\python.exe" -X utf8 generate_memos.py
```
